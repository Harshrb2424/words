# Words - Phase 4: LocalStorage-Backed Likes Engine, Capped Homepage Feed, and Layout Refinements

This document records the architectural details, database updates, and UI enhancements implemented during the Phase 4 milestones for the **Words** quote sanctuary.

---

## 💖 1. Interactive LocalStorage-Backed Likes Engine

To encourage reader engagement without forcing heavy user authentication or credentials, we developed a high-fidelity, client-cached anonymous likes system.

### A. Database Schema Migration
We executed a local Cloudflare D1 migration to append a persistent like-tracking column to the relational `quotes` table:
* **Migration SQL (`backend/schema.sql`):**
  ```sql
  ALTER TABLE quotes ADD COLUMN likes INTEGER DEFAULT 0;
  ```
* **Persistent Incrementing:** Like tallies are aggregated globally inside the D1 SQLite instance.

### B. Worker API Route Addition (`backend/index.ts`)
* **Endpoint:** `POST /api/quotes/:id/like`
* **Workflow:**
  1. Checks if the requested quote ID exists in the D1 store.
  2. Increments the `likes` tally dynamically within a single, atomic database query (`UPDATE quotes SET likes = ? WHERE id = ?`).
  3. Returns the fresh count as a JSON response (`{ success: true, likes: newLikesCount }`) with standard permissive CORS headers.

### C. Double-Vote Client-Side Prevention (`QuoteActions.tsx`)
To prevent spamming or accidental double-clicking, the voting state is double-checked and stored directly inside the browser's context:
* **LocalStorage Footprint:** Caches liked quote IDs under a centralized `words_liked_quotes` JSON list.
* **Optimistic Updates:** Upon clicking the heart button, the client immediately increments the local count and changes state to `liked: true`, disabling further actions.
* **Micro-Animations:** The pill scales slightly (`scale-105`) and fills the Lucide `<Heart />` icon with a vibrant rose-500 tint inside a soft pink gradient background.

### D. Masonry Card Likes Badge (`QuoteCard.tsx`)
Quotes that have received appreciation are marked with a beautiful, high-contrast like-count pill on the home page's Masonry grid:
* Next to the author signature, a subtle rose heart badge dynamically appears:
  ```tsx
  {typeof quote.likes === "number" && quote.likes > 0 && (
    <span className="inline-flex items-center gap-1 text-[11px] font-bold text-rose-500/85">
      <Heart className="h-3 w-3 fill-rose-500 stroke-rose-500" />
      <span>{quote.likes}</span>
    </span>
  )}
  ```

## ⚡ 2. Database-Driven Paginated Search & "Show More" Feed

To maintain instantaneous Time-to-First-Byte (TTFB) speeds while supporting seamless traversal of the entire quote archive, we transitioned the homepage from client-side filtering to a powerful **Database-Level Paginated Search and Load More** architecture:

### A. Paginated D1 Search API (`backend/index.ts`)
* **Endpoint:** `GET /api/quotes`
* **Query Parameters:**
  * `limit`: Max records to return (defaults to `1000`, configured as `30` in feed requests).
  * `offset`: Number of records to skip (enables page-by-page loading).
  * `q`: Search query string snippet matching quotes, authors, source themes, or tags.
* **SQL Compilation:**
  Dynamically compiles a safe parameter-bound query in SQLite/D1:
  ```sql
  SELECT * FROM quotes 
  WHERE quote_text LIKE ? OR author LIKE ? OR source LIKE ? OR tags LIKE ?
  ORDER BY id DESC LIMIT ? OFFSET ?
  ```

### B. Live Debounced Search (`QuotesArchive.tsx`)
* When a user inputs terms in the search bar, the UI triggers a **400ms debouncing window**.
* On expiration, it fires a dynamic HTTP fetch request targeting the backend Worker. The results are optimistically swapped into the client masonry state, keeping the client DOM light and ultra-responsive.

### C. Show More Paginated Loading (`QuotesArchive.tsx`)
* A premium, theme-colored `"Show More Quotes"` button is rendered at the bottom of the Masonry grid.
* Clicking it triggers paginated requests skipping `offset` records, appending them smoothly to the masonry display.
* If a fetch yields fewer than 30 quotes, the button dynamically hides, indicating the end of the archive catalog.
